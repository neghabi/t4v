# T4V

سرویس فارسی کوتاه‌سازی لینک و ساخت QR با حساب کاربری، داشبورد، اعتبار و API.

## اجرای محلی

Node.js نسخهٔ ۲۲ یا جدیدتر لازم است. در پوشهٔ پروژه اجرا کنید:

```sh
npm ci
npm run dev:local
```

سایت در http://localhost:3000 باز می‌شود. این دستور PostgreSQL محلی را روی
`127.0.0.1:55432` اجرا می‌کند، migrationها را اعمال می‌کند و سپس سایت را بالا می‌آورد.
داده‌ها در `.local/postgres-utf8` باقی می‌مانند. برای توقف، `Ctrl+C` بزنید؛ برای
اجرای دوباره همان دستور کافی است. اگر پورت ۳۰۰۰ اشغال است، متغیر `PORT` را تنظیم کنید.

تنظیمات و رمزهای تصادفی محلی در `.local/config.json` ذخیره می‌شوند. رمز ورود
ورود قدیمی مدیریت از مقدار `adminSecret` همین فایل استفاده می‌کند؛ پس از ساخت
حساب مدیر، نام کاربری و رمز حساب جدید جایگزین آن می‌شوند. این پوشه وارد Git یا بستهٔ استقرار نمی‌شود.
برای ایجاد حساب مدیر با نام کاربری، پس از اجرای migrationها و روشن شدن پایگاه داده
`npm run admin:create -- admin` را اجرا کنید. رمز تصادفی در `.local/admin-admin.json`
ذخیره می‌شود و در پایگاه داده فقط هش scrypt نگه داشته می‌شود. ورود از `/admin`
است؛ حساب مدیر به همهٔ امکانات مدیریت دسترسی دارد. ساخت دوباره، رمز حساب موجود
را عوض نمی‌کند. با وجود حساب مدیر، ورود قدیمی با `DASHBOARD_SECRET` غیرفعال است.
در استقرار مستقل، همین دستور را با `DATABASE_URL` صحیح اجرا کنید.
این محیط از UTF-8 برای متن فارسی و UTC برای ذخیرهٔ زمان‌ها استفاده می‌کند.

داشبورد جدید شامل عنوان و برچسب، شناسهٔ دلخواه، جست‌وجو، فیلتر وضعیت، گزارش‌های
۷/۳۰/۹۰ روزه و خروجی CSV است. در بخش امنیت، نشست‌ها، تغییر رمز و تأیید ایمیل
در دسترس‌اند. ایمیل‌های آزمایشی را در `/dev/mailbox` ببینید. بازیابی رمز از
`/forgot-password` انجام می‌شود. لینک‌های ایمیل یک‌بارمصرف‌اند.

در `dev:local`، پرداخت sandbox فعال است؛ هیچ مبلغ واقعی دریافت نمی‌شود.
تأیید تکراری پرداخت، اعتبار را دوباره اضافه نمی‌کند. صندوق ایمیل و sandbox
فقط با `NODE_ENV=development` و `T4V_LOCAL_SERVICES=true` فعال می‌شوند.
برای ایمیل یا پرداخت واقعی باید آداپتر سرویس مربوطه پیاده و تنظیم شود.

این دستور worker آمار را هم اجرا می‌کند. در استقرار مستقل، کنار سایت
`npm run worker` را با همان `DATABASE_URL` اجرا کنید؛ Compose سرویس worker دارد.
بازدیدها ابتدا در صف پایگاه داده ثبت و سپس به‌صورت اتمی پردازش می‌شوند؛ گزارش
ممکن است چند ثانیه تأخیر داشته باشد. جزئیات بازدید پس از ۹۰ روز پاک می‌شوند،
ولی شمارندهٔ کل لینک باقی می‌ماند. IP به‌صورت هش و referrer به‌صورت origin ذخیره
می‌شوند. تشخیص ربات و بازدیدکنندهٔ یکتا تقریبی است.

سند قابل‌پردازش API در `/api/openapi` و راهنما در `/api-docs` قرار دارد.
کلیدها دسترسی خواندن/نوشتن دارند. برای تکرار امن ساخت لینک، هدر
`Idempotency-Key` ثابت را همراه بدنهٔ یکسان استفاده کنید؛ بدنهٔ متفاوت خطای ۴۰۹
می‌دهد. شناسهٔ دلخواه ۳ تا ۳۲ نویسه، حداکثر ۸ برچسب و عنوان ۱۲۰ نویسه مجازند.
خروجی CSV تا ۵۰۰۰ لینک را با فیلتر فعلی شامل می‌شود.

## بررسی تغییرات

در حالی که `dev:local` فعال است:

```sh
npm run test:local
npm run lint
npx tsc --noEmit
```

آزمون محلی حساب‌های موقت خودش را می‌سازد و در پایان پاک می‌کند؛ ورود، مالکیت لینک،
اعتبار QR، تغییر رمز لینک، انقضا، آمار ۲۴ ساعت، صفحه‌بندی و محدودیت درخواست‌های
هم‌زمان را بررسی می‌کند. آزمون فقط پایگاه دادهٔ همین محیط محلی را هدف می‌گیرد.

## استقرار

برای اجرای Docker روی ویندوز، `scripts/docker-up.ps1` را اجرا کنید. برای سرور
دارای Docker و Docker Compose:

```sh
chmod +x deploy/install.sh
./deploy/install.sh t4v.ir
```

برای ساخت نسخهٔ نهایی، `DATABASE_URL`، `APP_SECRET` (حداقل ۳۲ نویسه) و
`PUBLIC_SHORT_URL_BASE` را تنظیم و `npm run build` را اجرا کنید. دامنهٔ عمومی
در متادیتا، sitemap و لینک‌های تولیدشده از `PUBLIC_SHORT_URL_BASE` خوانده می‌شود.
API فهرست لینک‌ها، ۲۵ نتیجه در هر صفحه می‌دهد؛ صفحهٔ بعد با `?page=2` قابل دریافت است.
