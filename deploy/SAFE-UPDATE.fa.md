# به‌روزرسانی سرور موجود بدون تغییر رمزها

این روش برای سرور فعلی با سرویس‌های `db` و `web` و فایل `compose.auth-repair.yml` است. برای نصب تازه نیست. فایل‌های Compose سرور و `.env` را حفظ کنید. بسته به‌روزرسانی جدید فایل Compose اصلی را جایگزین نمی‌کند. صرفاً restart کردن، کد تازه را داخل تصویر Docker قرار نمی‌دهد.

پس از بارگذاری و استخراج بسته جدید در `/var/www/t4v-site` اجرا کنید:

```bash
cd /var/www/t4v-site
bash deploy/update-existing.sh
```

این دستور به‌ترتیب نسخه تازه را می‌سازد، اتصال دیتابیس نسخه تازه را بررسی می‌کند، از دیتابیس پشتیبان می‌گیرد، migration را اجرا می‌کند، کامل بودن schema و تنظیمات واقعی کانتینر جدید وب را می‌سنجد و سپس وب و پردازشگر گزارش را جایگزین می‌کند. قفل اجرای هم‌زمان دارد. رمز یا کلید جدید تولید نمی‌کند و حساب مدیر را تغییر نمی‌دهد.

با هر خطای پیش از جایگزینی وب، فرایند متوقف می‌شود و کانتینر قبلی وب جایگزین نمی‌شود. migrationها می‌توانند دیتابیس را تغییر دهند؛ پشتیبان خصوصی در `backups` است. بازگشت خودکار دیتابیس انجام نمی‌شود و همه تغییرات آینده لزوماً با نسخه قدیمی سازگار نیستند. سلامت بعد از انتشار نیز کنترل می‌شود. این روند جای استقرار بدون وقفه یا نسخه‌بندی کامل زیرساخت را نمی‌گیرد.

## معنی خطاها

- `28P01`: رمز موجود در اتصال برنامه با نقش PostgreSQL هماهنگ نیست. رمز دیتابیس به‌صورت خودکار عوض نمی‌شود؛ مقدار درست باید در `.env` باقی بماند. تغییر `POSTGRES_PASSWORD` در Compose رمز دیتابیس قبلاً ساخته‌شده را تغییر نمی‌دهد.
- `DATABASE_URL_INVALID`: آدرس اتصال تنظیم نشده یا معتبر نیست. نام کاربر/دیتابیس درست به‌تنهایی درستی رمز را اثبات نمی‌کند.
- `APP_SECRET_INVALID`: کلید برنامه در محیط واقعی سرویس وب وجود ندارد یا کوتاه است. کلید قبلی را برگردانید؛ کلید جدید باعث بی‌اعتبار شدن نشست‌های قدیمی می‌شود.
- `MIGRATION_PENDING`: فایل‌های پروژه جدیدند ولی همه تغییرات دیتابیس اجرا نشده‌اند.
- `MIGRATION_FAILED`: یک migration ناموفق باقی مانده است؛ گزارش همان migration را بررسی کنید. بدون بررسی تغییرات اجراشده، migration را موفق یا برگشت‌خورده علامت نزنید.
- `42P01` یا `42703`: جدول یا ستون لازم موجود نیست یا ساختار واقعی با migration ثبت‌شده تطبیق ندارد.

خطای بررسی فقط کد فنی را چاپ می‌کند؛ رمز، آدرس اتصال و اطلاعات کاربران چاپ نمی‌شوند. اگر مرحله‌ای شکست خورد، همان خروجی و نام مرحله را برای بررسی نگه دارید. از حذف volume، `migrate reset` یا ساخت مجدد حساب‌ها استفاده نکنید.

## بررسی نهایی

```bash
curl -fsS https://t4v.ir/api/health
docker compose -f docker-compose.yml -f compose.auth-repair.yml logs --since=5m --tail=100 web
```

بررسی سلامت جدید، علاوه بر اتصال، ستون‌های لازم احراز هویت و تنظیمات ارسال را هم بررسی می‌کند. برای مشاهده پرونده و تنظیم سرویس‌های ارسال، راهنمای `IDENTITY-AND-MODERATION.fa.md` و برای گزارش‌ها `REPORTING-UPDATE.fa.md` را ببینید. اگر ورود با نشست موجود مشکل دارد، پاسخ JSON و شناسه درخواست را نگه دارید؛ پاک‌کردن کوکی جای اصلاح دیتابیس نیست.
