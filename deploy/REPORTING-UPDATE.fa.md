# انتشار گزارش مصرف، کلیک و احراز هویت روی سرور فعلی

این راهنما مخصوص `/var/www/t4v-site` با سرویس‌های `db` و `web` و فایل موجود `compose.auth-repair.yml` است. فایل Compose اصلی و `.env` را جایگزین نکنید. رمز کاربر دیتابیس باید با `DATABASE_URL` وب یکسان باشد؛ سلامت دیتابیس را قبل از انتشار بررسی کنید.

## تفاوت محلی و اصلی

وجود قابلیت در فایل‌های پروژه، به معنی انتشار روی سرور نیست. کد، وابستگی‌ها و migrationها باید بارگذاری شوند، تصویر Docker دوباره ساخته شود و کانتینر وب با تنظیمات صحیح جایگزین شود. restart به‌تنهایی کد تازه را وارد تصویر نمی‌کند.

نشانی‌های نسخه جدید:

- `/dashboard/identity`: تأیید ایمیل و موبایل، پرونده و بارگذاری مدارک خصوصی.
- `/admin`: مدیریت کاربران؛ با بازکردن پرونده، مدارک و تأیید یا تعلیق کاربر و لینک‌ها در دسترس است.
- `/admin/settings`: تنظیم سرویس ایمیل و پیامک؛ تا پیش از تنظیم سرویس واقعی، ارسال عملیاتی غیرفعال است.
- `/admin/reports`: گزارش مصرف اعتبار کاربران، کلیک‌های اخیر، دفتر اعتبار و وضعیت صف.

مدارک رمزنگاری می‌شوند و کلید ثابت خصوصی لازم دارند. راهنمای `IDENTITY-AND-MODERATION.fa.md` را برای کلید و سرویس‌ها بخوانید. حالت محلی هرگز جایگزین تأیید واقعی روی سرور نیست.

## مراحل انتشار

۱. فایل بسته جدید را روی سرور استخراج کنید؛ فایل‌های `.env`، Compose و پشتیبان‌های موجود را حفظ کنید. سپس:

```bash
cd /var/www/t4v-site
mkdir -p backups
backup="backups/before-reporting-$(date -u +%Y%m%dT%H%M%SZ).dump"
docker compose exec -T db pg_dump -U t4v_admin -d t4v_production -Fc > "$backup" && chmod 600 "$backup"
```

اگر پشتیبان‌گیری خطا داد، ادامه ندهید.

۲. از وجود `DATABASE_URL` صحیح در `.env` و تنظیم کلید ثابت رمزنگاری در محیط سرویس web اطمینان حاصل کنید. کلید قدیمی را تغییر ندهید. سپس با هر دستور موفق به مرحله بعد بروید:

```bash
docker compose -f docker-compose.yml -f compose.auth-repair.yml build web auth-migrate
docker compose -f docker-compose.yml -f compose.auth-repair.yml run --rm --no-deps auth-migrate
docker compose -f docker-compose.yml -f compose.auth-repair.yml up -d --no-deps --force-recreate web
curl -fsS https://t4v.ir/api/health
```

خطای migration را نادیده نگیرید. web هنگام migration باید روشن باشد، چون سرویس نگهداری فعلی شبکه آن را استفاده می‌کند. migration احراز هویت، لینک‌های قدیمی را نیز تا بررسی مدیر معلق می‌کند.

۳. فایل پردازشگر همراه بسته را در کنار Compose فعلی کپی کنید. این فایل فقط یک سرویس اضافه می‌کند و پورت یا حجم دیتابیس را تغییر نمی‌دهد:

```bash
cp deploy/compose.reporting.yml compose.reporting.yml
docker compose -f docker-compose.yml -f compose.auth-repair.yml -f compose.reporting.yml build analytics-worker
docker compose -f docker-compose.yml -f compose.auth-repair.yml -f compose.reporting.yml up -d --no-deps analytics-worker
docker compose -f docker-compose.yml -f compose.auth-repair.yml -f compose.reporting.yml ps analytics-worker
docker compose -f docker-compose.yml -f compose.auth-repair.yml -f compose.reporting.yml logs --tail=80 analytics-worker
```

پردازشگر جدید شبکه کانتینر db را استفاده می‌کند. پس از بازسازی کانتینر دیتابیس، پردازشگر را نیز با `up -d --no-deps --force-recreate analytics-worker` و همان سه فایل دوباره ایجاد کنید. در تمام دستورات نگهداری، فایل‌های override را حفظ کنید. از حذف volume یا `migrate reset` استفاده نکنید.

## چرا کلیک‌ها در گزارش نبودند؟

مسیر کوتاه، بازدید موفق را ابتدا در `click_events` ذخیره می‌کند. پردازشگر آن را به `link_clicks` منتقل و شمارنده لینک را افزایش می‌دهد. بدون پردازشگر، صف باقی می‌ماند و گزارش به‌روز نمی‌شود. بازدیدهای منتظر پردازش در نسخه جدید نمایش داده می‌شوند. پس از راه‌اندازی، رویدادهای باقی‌مانده برای لینک‌های موجود نیز پردازش می‌شوند؛ درخواست‌هایی که هیچ‌گاه ثبت نشده‌اند قابل بازسازی نیستند.

داشبورد کاربر ربات‌های قابل‌شناسایی را حذف می‌کند؛ شمارنده کل و رویدادهای مدیریتی شامل ربات‌ها هستند. بازدیدکننده یکتا تقریبی و بر اساس هش IP است؛ معادل تعداد انسان‌ها نیست. کلیک هزینه اعتبار ندارد؛ مصرف اعتبار از برداشت‌های دفتر اعتبار محاسبه می‌شود. جزئیات کلیک تا ۹۰ روز حفظ می‌شود، ولی شمارنده لینک موجود باقی می‌ماند. حذف لینک، سابقه بازدید وابسته را نیز حذف می‌کند. این گزارش آرشیو قانونی دائمی نیست.

## بررسی پس از انتشار

۱. سلامت دیتابیس باید `connected` باشد و ورود کار کند.
۲. در ثبت‌نام، اطلاعات فعالیت و موبایل دیده شود؛ کاربر مسیر پرونده را ببیند و مدیر تنظیمات ارتباطات و پرونده کاربران را ببیند.
۳. با سرویس ارسال تنظیم‌شده، یک حساب آزمایشی ایمیل و موبایل را تأیید و مدرک بارگذاری کند. مدیر مدرک، پرونده و لینک را بررسی کند. لینک تأییدنشده نباید هدایت شود.
۴. یک لینک فعال را باز کنید؛ پس از چند ثانیه `/admin/reports` را تازه کنید. صف باید تخلیه شود و کلیک ظاهر شود. اگر صف بیش از یک دقیقه باقی ماند، گزارش پردازشگر را بررسی کنید.
۵. ساخت لینک و تغییر اعتبار باید در دفتر اعتبار دیده شود. فهرست کاربران گزارش صفحه‌بندی و جست‌وجو دارد؛ ۵۰ رویداد اخیر مربوط به کل سامانه است.
